LegendHDF5IO.jl

LegendHDF5IO reads and writes HDF5 files that follow the LEGEND LH5 data format. Such files store arrays, tables, waveforms, histograms and nested structures together with datatype and units attributes, and are interoperable with the Python package legend-pydataobj.

Getting started

Open a file with lh5open, which returns an LHDataStore. Write with setindex!, read with getindex:

using LegendHDF5IO, Unitful

lh5open("data.lh5", "cw") do lhd
    lhd["energy"] = rand(1000) .* u"keV"
    lhd["metadata"] = (detector = "V01234A", threshold = 5.0u"keV")
end

lh5open("data.lh5") do lhd
    E = lhd["energy"]       # lazy, disk-backed LH5Array
    E_first = E[1:100]      # reads only the first 100 elements
    E_some = E[[1, 7, 42]]  # scattered reads are efficient, too
    E_all = E[:]            # reads the full array
    lhd["metadata"]         # NamedTuples are read back directly
end

Datasets are wrapped as lazy LH5Arrays, so slicing reads only the requested part of the data from disk. Arrays of Enums, StaticVectors and NTuples are the exception and are read eagerly. LH5Array implements the DiskArrays.jl interface: views, iteration and reductions like sum read the data block by block, and broadcasts over LH5Arrays are lazy, evaluated chunk by chunk when collected or written, so selecting columns with PropertyFunctions opens the columns without reading their values. map is eager, as in Base. Datasets opened for writing can be modified in place within their current size (E[1:10] = ...); append! grows them. Nested structures (NamedTuples, tables, waveforms) are represented as HDF5 groups. Views of empty ranges and empty elements of lazily read vectors of vectors are not supported by DiskArrays yet; read such data with [:] first.

Tables and waveforms

Tables and vectors of RDWaveforms round-trip through their LH5 representation. Tables are read as LH5LazyTables, which open a column when it is accessed and not before, so reading a few columns of a wide table costs a few reads instead of one per column. They satisfy the Tables.jl column interface, and treating one as an array (broadcasting, indexing, iteration) converts it to a StructArray of NamedTuple rows over all columns. Anything that satisfies the Tables.jl column interface can be written:

using StructArrays, ArraysOfArrays, RadiationDetectorSignals

tbl = StructArray((
    evtno = collect(1:100),
    energy = rand(100) .* u"keV",
    samples = VectorOfVectors([rand(-5:5, 50) for _ in 1:100]),
))

wfs = ArrayOfRDWaveforms((
    fill(range(0.0u"μs", 10.0u"μs", length = 1000), 100),
    VectorOfSimilarVectors(rand(UInt16, 1000, 100)),
))

lh5open("events.lh5", "cw") do lhd
    lhd["evt"] = tbl
    lhd["raw/waveform"] = wfs
end

Reading lhd["evt"] returns an LH5LazyTable; lhd["evt"][:], or indexing with a range, reads the rows into a StructArray. A table handle keeps the column names it was opened with: columns added through other handles are not visible to it, reading a column deleted elsewhere fails, and append! refuses when the set of column names has changed. Lazy tables cannot be concatenated with vcat; read them first.

Scattered reads either read the whole index span the events cover, or the events themselves. The thresholds for that choice, LegendHDF5IO.scatter_bulk_max_bytes and LegendHDF5IO.scatter_bulk_max_waste, are tuned for local storage by default; raise them on filesystems with a high per-operation latency, such as cluster filesystems.

Appending and compression

Open the file with usechunks = true to create extensible array datasets, then grow them with append! (always along the last dimension):

lh5open("events.lh5", "cw", usechunks = true) do lhd
    lhd["evt"] = tbl
    append!(lhd["evt"], tbl)
end

The chunk size is taken from the first array written to each dataset. With compress = :zstd (or true) array datasets are Zstandard-compressed; compress = :deflate uses shuffle plus deflate for maximum portability. Compressed datasets are always chunked, so they compose with append!. Appends are not transactional: one that fails midway, for example because a value cannot be converted to the element type of a column, leaves the columns it has already extended longer than the others.

Modifying structure

Columns and struct fields can be added and removed in place with add_entries! and delete_entry!:

lh5open("events.lh5", "r+") do lhd
    add_entries!(lhd, "evt", StructArray((quality = rand(Bool, 100),)))
    delete_entry!(lhd, "evt/quality")
end

Geant4 output

Hit tables from Geant4 simulations in GEARS or g4simple HDF5 layout can be read with Geant4HDF5Input:

hits = open(read, "simulation.hdf5", Geant4HDF5Input)

Supporting custom types

Additional types can be supported by registering an LH5 datatype name and defining a reader and a writer:

struct ChannelNo
    no::Int
end

LegendHDF5IO.register_datatype!("channelno", ChannelNo)

LegendHDF5IO.LH5Array(ds::HDF5.Dataset, ::Type{<:ChannelNo}) =
    ChannelNo(read(ds))

function LegendHDF5IO.create_entry(parent::LHDataStore, name::AbstractString,
    x::ChannelNo; kwargs...)
    parent.data_store[name] = x.no
    LegendHDF5IO.setdatatype!(parent.data_store[name], ChannelNo)
    nothing
end

Enum types only need registration: LegendHDF5IO.register_datatype!(MyEnum).

A name can be registered for one type only, and a type under one name only. Conflicting registrations, and built-in names like "real", are rejected with an ArgumentError.

The readdata/writedata API

The functions LegendDataTypes.readdata and LegendDataTypes.writedata provide an eager alternative that operates directly on HDF5.File or HDF5.Group objects:

using HDF5
import LegendDataTypes: readdata, writedata

HDF5.h5open("data.lh5", "w") do f
    writedata(f, "energy", rand(1000) .* u"keV")
end

E = HDF5.h5open(f -> readdata(f, "energy"), "data.lh5")
