    LegendHDF5IO.AbstractLH5Table — Type
    AbstractLH5Table{R<:NamedTuple} <: AbstractVector{R}

    Supertype of the lazy tables of LH5 data: LH5LazyTable, LH5JoinedTable, LH5ChainedTable and LH5TypedTable.

    A lazy table is a vector of NamedTuple rows. Its column names are known up front, the element type of a column only once the column is opened, so the row type R is the abstract NamedTuple, except for typed tables. Accessing a column, with tbl.colname or Tables.getcolumn, opens that column and no other, and Tables.columns(tbl) is a dictionary of the columns (see LH5LazyColumns). Column-wise broadcasts, such as PropertyFunctions, open only the columns they use, and PropertyFunctions selections return typed tables.

    Treating the table as an array opens all columns. Indexing with a range, index vector or mask reads the selected rows into a StructArray, and tbl[:] reads the whole table. Iteration reads the rows in blocks of a few thousand, so loops, comprehensions and map read neither one row at a time nor everything at once. filter, findall and reductions go through iteration, while sort and sortperm read the table first. vcat of lazy tables chains them, and concatenation with other arrays is refused. So is StructArray(tbl): once a column was read eagerly, such a StructArray would slice and append rows with a stale row type and bypass the append checks.

    Lazy tables stop working when the file they read from is closed. The rows read from them do not.

    Implementation

    Subtypes implement _table_colnames(tbl), _column(tbl, name) and length(tbl), and may specialize _typed_table(tbl), _getindex_rows(tbl, idxs) and the block iteration, _next_block.

    LegendHDF5IO.LH5Array — Type
    LH5Array{T, N} <: AbstractArray{T, N}

    Array wrapper for an HDF5.Dataset following the LEGEND data format, as in ".lh5" files.

    getindex reads only the requested part of the on-disk array. append! extends the on-disk array along its last dimension, which requires a chunked dataset.

    LH5Array implements the DiskArrays.jl interface: views, iteration and reductions read the data chunk by chunk, broadcasts are lazy, and setindex! writes back into the dataset within its current size.

    Default constructors

    LH5Array{T, N}(ds::HDF5.Dataset)
LH5Array{T}(ds::HDF5.Dataset)
LH5Array(ds::Union{HDF5.Dataset, HDF5.H5DataStore})

    Example

    julia> using HDF5
julia> f = h5open("path/to/lh5/file", "r")
julia> lh = LH5Array(f["path/to/HDF5/Dataset"])
[...]
julia> x = lh[1:10]     # load the first 10 elements of the on-disk array
[...]
julia> append!(lh, x)   # append those 10 elements to the on-disk array
[...]

    LegendHDF5IO.LH5ChainedTable — Type
    LH5ChainedTable <: AbstractLH5Table

    Tables one after the other, without reading them. vcat and reduce(vcat, ...) of lazy tables return one, as do ArraysOfArrays.vecflattened of a vector of lazy tables and indexing a file chain with the path of a table (see LH5FileChain).

    Rows are read from the parts that hold them, so first(tbl, n) reads the first parts only. Accessing a column concatenates the columns of all parts lazily, which opens the column in each part. The parts must have the same columns, and rows take the column order of the first part. Chained tables and their columns are read-only.

    source
    LegendHDF5IO.LH5FileChain — Type
    LH5FileChain

    LH5 files of the same structure, read as one. lh5open of a vector of file names returns one.

    chain[path] concatenates the table or array at path over all files, as an LH5ChainedTable for a table. Files are opened when they are read from, and at most max_open of them stay open. Objects from the chain stop working when the chain is closed.

    The first file defines the structure: the column names of tables, and the datatypes, units, codecs, element types and inner sizes of what they hold. Other files are checked against it when a column is first read from them, so they need to agree only on what is read. Chains are read-only.

    source
    LegendHDF5IO.LH5JoinedTable — Type
    LH5JoinedTable <: AbstractLH5Table

    The columns of several tables side by side, without reading them. PropertyFunctions.innermerge returns one for lazy tables, and so does Tables.materializer of a lazy table when given columns that read from disk.

    The parts are lazy tables or NamedTuples of columns. They must have the same length, which is compared when the length of the join is needed, so joining chained tables opens no file. A column comes from the last part that has it, and the columns are ordered by their first occurrence, as in merge. append! refuses joined tables. Their columns are those of the parts, so writing to a column writes to its part.

    LegendHDF5IO.LH5LazyTable — Type
    LH5LazyTable <: AbstractLH5Table

    A table stored in an LH5 file whose columns are opened on demand. Reading a table returns one. It behaves as described for AbstractLH5Table, and append! appends to the stored columns.

    Extended help

    Opening a column reads its "datatype" attribute, and for a vector of vectors its cumulative_length as well. The attribute lives in the dataset's object header, which HDF5 usually places next to the column's data rather than next to the other headers, so opening a wide table eagerly costs one scattered read per column plus the cumulative_length arrays. On a network file system that is the dominant cost of opening a file whose columns are mostly unused.

    Neither the column names nor the column types are type parameters, so opening a table compiles no code specialized on them. Column access is therefore not inferable, which costs little in practice: the datatype attributes are only read at run time, so code that loops over rows has to pass the selected columns through a function boundary either way.

    LegendHDF5IO.LH5TypedTable — Type
    LH5TypedTable{R<:NamedTuple} <: AbstractLH5Table{R}

    A lazy table with a fixed row type. PropertyFunctions selections over lazy tables return one: (@pf (e = $energy, t = $timestamp)).(tbl) has the columns energy and timestamp of tbl under the names e and t, and nested paths such as $geds.energy select from nested tables. The row type, and the types of the columns of a block of rows, are fixed when the selection is made, from the columns of the first file, which is the only file a selection over a file chain opens. So rows read with a range or an index vector, iteration and filterby have inferable types, and Tables.schema is known.

    Rows are read from the selected columns only. Blocks of rows take the column types of the first part of a chain and convert those of the other parts, and a value that does not fit throws. The columns, sel.e, are the lazy columns of the table selected from. append! refuses typed tables.

    LegendHDF5IO.LHDataStore — Type
    LHDataStore <: AbstractDict{String,Any}

    Dictionary wrapper for an HDF5.H5DataStore (typically an HDF5.File, or an HDF5.Group) following the LEGEND data format, as in ".lh5" files.

    Constructor:

    LHDataStore(h5ds::HDF5.H5DataStore, usechunks::Bool, compress::Symbol = :none)

    To open ".lh5" files directly, without HDF5.h5open, use lh5open.

    getindex(lh::LHDataStore, s) returns the output of LH5Array applied to lh.data_store[s], so arrays other than those of Enums, StaticVectors, NTuples and Measurements are wrapped lazily. setindex! creates and writes HDF5.Groups and HDF5.Datasets.

    With usechunks = true, array datasets are created chunked, so append! can extend them, and the first array written sets the chunk size. With compress set to :zstd or :deflate, array datasets are chunked and compressed, with chunks of at most 1 MiB.

    Supported value types include RealQuantity and arrays thereof, Bool, String, Symbol, Enums, (arrays of) NTuples and StaticVectors, ArrayOfSimilarArrays, VectorOfVectors, encoded arrays, NamedTuples, tables, AbstractVector{<:RDWaveform} and Histogram. For arrays, the last axis is assumed to correspond to the event number index.

    Example

    julia> lhf = lh5open("path/to/lh5/file", "cw")
julia> lhf["raw"]
[...]
julia> using Unitful
julia> x = rand(100) * u"ns"
julia> lhf["new"] = x
[...]

    LegendHDF5IO.scatter_bulk_max_bytes — Constant
    LegendHDF5IO.scatter_bulk_max_bytes[]

    Size up to which a scattered read reads the whole index span its events cover, instead of reading the events themselves.

    Reading the span costs one read operation. Reading the events costs one scattered selection, or one read per run of adjacent events, depending on element type, rank and layout. With the default nothing the limit depends on the file system the file lives on: 1 MiB on local storage and 8 MiB on network file systems such as GPFS, NFS or Lustre, where fewer and larger reads pay off. Variable-length elements like strings are always read selectively. Can also be set per environment as the preference "scatterbulkmax_bytes".

    See also LegendHDF5IO.scatter_bulk_max_waste.

    source
    LegendHDF5IO.scatter_bulk_max_waste — Constant
    LegendHDF5IO.scatter_bulk_max_waste[]

    Factor by which a scattered read may exceed the requested amount of data when it reads the whole index span its events cover.

    Densely covered spans are read as a whole however large they are, so raising this trades reading more data for fewer read operations. With the default nothing the factor is 4 on local storage and 16 on network file systems. Spans up to LegendHDF5IO.scatter_bulk_max_bytes are read as a whole regardless. Can also be set per environment as the preference "scatterbulkmax_waste".

    LegendHDF5IO.register_datatype! — Method
    LegendHDF5IO.register_datatype!(name::AbstractString, ::Type{T})
LegendHDF5IO.register_datatype!(::Type{T})

    Register the LH5 datatype string name for type T, for reading and writing. Without name, the canonical datatype string of T is used (e.g. for Enum types).

    Each name can only be registered for one type, and each type only under one name. Names consist of letters and underscores. Built-in datatype names like "real" or "array<1>{real}" are reserved. Conflicting registrations throw an ArgumentError, while repeating a registration has no effect.

    The registry is not part of the precompilation cache, so register from the __init__ function of your module or package extension.

    For a type T without built-in support, also define

    LegendHDF5IO.LH5Array(ds::HDF5.Dataset, ::Type{<:T})
LegendHDF5IO.create_entry(parent::LHDataStore, name::AbstractString, x::T; kwargs...)
