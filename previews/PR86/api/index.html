    LegendHDF5IO.LH5Array — Type
    LH5Array{T, N} <: AbstractArray{T, N}

    Array wrapper for an HDF5.Dataset following the LEGEND data format, as in ".lh5" files.

    getindex reads the requested part of the on-disk array, so data can be read partially without loading the whole array first. append! extends the on-disk array (which requires it to be chunked); data is always appended along the last dimension.

    LH5Array implements the DiskArrays.jl interface: views, iteration and reductions read the data block by block, broadcasts are lazy, and setindex! writes back into the dataset within its current size.

    Default constructors

    LH5Array{T, N}(ds::HDF5.Dataset)
LH5Array{T}(ds::HDF5.Dataset)
LH5Array(ds::Union{HDF5.Dataset, HDF5.H5DataStore})

    Example:

    julia> using HDF5
julia> f = h5open("path/to/lh5/file", "r")
julia> lh = LH5Array(f["path/to/HDF5/Dataset"])
[...]
julia> x = lh[1:10]     # load the first 10 elements of the on-disk array
[...]
julia> append!(lh, x)   # append those 10 elements to the on-disk array
[...]

    LegendHDF5IO.LH5LazyTable — Type
    LH5LazyTable

    A table stored in an LH5 file whose columns are opened on demand.

    Reading a table returns one of these. Accessing a column, with tbl.colname or Tables.getcolumn, opens that column and no other. Anything that treats the table as an array (broadcasting, indexing, iteration) opens all of them, as it must.

    Extended help

    Opening a column reads its "datatype" attribute, and for a vector of vectors its cumulative_length as well. The attribute lives in the dataset's object header, which HDF5 usually places next to the column's data rather than next to the other headers, so opening a wide table eagerly costs one scattered read per column plus the cumulative_length arrays. On a cluster filesystem that is the dominant cost of opening a file whose columns are mostly unused.

    Neither the column names nor their types are part of the type, so opening a table specializes no code on its column types. Column access is therefore not inferrable, which costs little in practice: the datatype attributes are only read at run time, so code that loops over rows has to pass the selected columns through a function boundary either way.

    LegendHDF5IO.LHDataStore — Type
    LHDataStore <: AbstractDict{String,Any}

    Dictionary wrapper for an HDF5.H5DataStore (typically an HDF5.File, but may also be e.g. an HDF5.Group) following the LEGEND data format, as in ".lh5" files.

    Constructor:

    LHDataStore(h5ds::HDF5.H5DataStore, usechunks::Bool, compress::Symbol = :none)

    To read from or write to ".lh5" files directly (without using HDF5.h5open first), use lh5open.

    getindex(lh::LHDataStore, s) returns the output of LH5Array applied to lh.data_store[s], so arrays other than those of Enums, StaticVectors and NTuples are wrapped lazily. setindex! creates and writes HDF5.Groups and HDF5.Datasets. With usechunks = true array datasets are created chunked and extensible, so they can later be extended with append!; the chunk size is taken from the first array written. With compress set to :zstd or :deflate, array datasets are chunked and compressed. Supported value types include RealQuantity and arrays thereof, Bool, String, Symbol, Enums, (arrays of) NTuples and StaticVectors, ArrayOfSimilarArrays, VectorOfVectors, encoded arrays, NamedTuples, tables, AbstractVector{<:RDWaveform} and Histogram. For arrays, the last axis is assumed to correspond to the event number index.

    Example

    julia> lhf = lh5open("path/to/lh5/file", "cw")
julia> lhf["raw"]
[...]
julia> using Unitful
julia> x = rand(100) * u"ns"
julia> lhf["new"] = x
[...]

    LegendHDF5IO.scatter_bulk_max_bytes — Constant
    LegendHDF5IO.scatter_bulk_max_bytes[]

    Size up to which a scattered read reads the whole index span its events cover, instead of reading the events themselves (1 MiB by default).

    Reading the span costs one read operation. Reading the events costs one scattered selection, or one read per run of adjacent events, depending on element type, rank and layout. The default suits local storage; on filesystems with a high per-operation latency, such as cluster filesystems, fewer and larger reads pay off, so raise it there. Variable-length elements like strings are always read selectively. Can also be set per environment as the preference "scatterbulkmax_bytes".

    See also LegendHDF5IO.scatter_bulk_max_waste.

    source
    LegendHDF5IO.scatter_bulk_max_waste — Constant
    LegendHDF5IO.scatter_bulk_max_waste[]

    Factor by which a scattered read may exceed the requested amount of data when it reads the whole index span its events cover (4 by default).

    Densely covered spans are read as a whole however large they are, so raising this trades reading more data for fewer read operations. Spans up to LegendHDF5IO.scatter_bulk_max_bytes are read as a whole regardless. Can also be set per environment as the preference "scatterbulkmax_waste".

    LegendHDF5IO.lh5open — Function
    lh5open(filename::AbstractString, access::AbstractString = "r";
    usechunks::Bool = false, compress = false)

    Open a LEGEND HDF5 file and return an LHDataStore object.

    With usechunks = true, newly written array datasets are chunked and can be extended with append!. compress selects their compression: true or :zstd for Zstandard, :deflate (alias :gzip) for shuffle plus deflate; compressed datasets are always chunked. LEGEND HDF5 files typically use the file extension ".lh5".

    LegendHDF5IO.register_datatype! — Method
    LegendHDF5IO.register_datatype!(name::AbstractString, ::Type{T})
LegendHDF5IO.register_datatype!(::Type{T})

    Register the LH5 datatype string name for type T, for reading and writing. Without name, the canonical datatype string of T is used (e.g. for Enum types).

    Each name can only be registered for one type, and each type only under one name. Built-in datatype names like "real" or "array<1>{real}" are reserved. Conflicting registrations throw an ArgumentError, while repeating a registration has no effect.

    For a type T without built-in support, also define
